# Quick wins 0.0.2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Eight small improvements learned from DimoMaint, shipped together as 4C CMMS 0.0.2.

**Architecture:**
- New behaviour rules are organization settings on `TenantSettings`. They are stored as JSON, so there is no migration, and they default to off.
- Server changes sit in the existing minimal-API feature files, plus one new `AlertEndpoints.cs`.
- Web changes are in the existing React + Mantine pages, plus one new print page and one bell component.

**Tech Stack:** ASP.NET Core 10 minimal APIs, EF Core (SQL Server), xUnit + `SkippableFact` integration tests, React 19 + Mantine 8 + TanStack Query + react-i18next.

**Spec:** `docs/superpowers/specs/2026-11-19-quick-wins-0.0.2-design.md`

**How to run things:** there is no .NET or Node on the Mac. Use the scratchpad helpers:
- `wt-test [filter]`: server tests in the .NET SDK container against the compose SQL Server. It prints `Passed!`/`Failed!` and `exit=N`. The full log is `scratchpad/last-test.log`.
- `wt-web`: `npm ci && npm run build` (tsc + vite) in a Node container. It prints errors and `exit=N`.

Docker Desktop and `cmmsx-sql-1` must be running.

## Global Constraints

- No EF migration. New settings live on `TenantSettings` (`server/FourC.Cmms.Core/Tenancy/Tenant.cs`).
- Every new setting defaults to off or empty. Existing organizations see no behaviour change.
- Reuse the existing permission codes (`Permissions` in `Identity.cs`). Add no new ones.
- All UI text goes through `t()`, with English strings in `web/src/locales/en.json`.
- Mirror every new setting in `web/src/api/types.ts` (the `TenantSettings` type) and show it on the Settings page, Organization tab (`SettingsPage.tsx`, beside `requireCompletionNotes`).
- One commit per task on `feature/quick-wins-0.0.2`, ending with the attribution line `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Never commit to `main`, never push.

## Review Focus

1. **All seven weekdays marked non-working.** Generation must not loop or crash. The settings save is rejected with "Leave at least one working day.", and `PmCalendar.NextWorkingDay` returns the date unchanged (Task 1).
2. **Organizations saved before 0.0.2** (settings JSON without the new keys). Everything reads as off or empty (Task 1, `TenantSettingsTests`).
3. **Checklist edits that don't tick a step** (a reading or remark only, or un-ticking), and work that is On hold. None of these starts the work automatically (Task 3).
4. **"All steps done" on a work order with no checklist** passes, because there is nothing to tick (Task 2).
5. **Created-date filter boundaries.** `createdFrom=today&createdTo=today` includes work created today, in UTC (Task 4).
