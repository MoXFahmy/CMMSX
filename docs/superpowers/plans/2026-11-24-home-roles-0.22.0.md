# Home pages and roles — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** CMX 0.22.0 — role home pages (card catalogue, shortcut tiles), personal counter tiles from saved views, menu tidying per role, role default columns, duplicate role.

**Architecture:** A role carries its home (`HomeLayout`, JSON) and hidden menu items (`HiddenModules`); role default columns live in a new `RoleListSettings` table; saved views gain a home pin. `/auth/me` returns the person's merged home; the web index route renders that home (role cards through a card grid) or today's dashboard unchanged. Each toolkit list's address-to-query mapping moves into one shared module so counters and list cards ask the list endpoints exactly what the list pages ask.

**Tech Stack:** ASP.NET Core 10 minimal APIs, EF Core 10 (SQL Server), xUnit SkippableFact + ApiFixture; React 19 + Mantine 8 + TanStack Query + i18next, Vitest.

**Spec:** `docs/superpowers/specs/2026-11-24-home-roles-0.22.0-design.md`

## Global Constraints

- Every new text in en + ar (web `web/src/locales/{en,ar}.json` via loc-add.py; server messages in `server/FourC.Cmms.Api/Localization/ar.json` via ar-add.py; Arabic plurals need _zero/_one/_two/_few/_many/_other).
- No new permissions. Role home, menu, columns and duplicate are under the existing `/roles` group (users.manage). Pins and the person's own column reset need only a sign-in.
- Older clients never clear new fields: `RoleInput.Home` and `RoleInput.HiddenModules` default to null, and null leaves the stored value unchanged.
- Limits (verbatim from the spec): 20 cards per role; 12 tiles per shortcuts card; tile label and Arabic label up to 40 characters, label required; link up to 300 characters, starts with `/`, not `//`, no scheme, no backslash; colours blue, teal, green, orange, red, grape, indigo, gray; 24 pinned views per person.
- Today's dashboard, for people without a role home, looks exactly as it does today.
- Cards never fetch data the person couldn't fetch from the list; a card the person can't use is left out.
- Gate with CI's exact build (`wt-ci`), plus `wt-vitest` and `wt-web`. All commands run with `WT=/Users/mohamedfahmy/Projects/CMMSX/.worktrees/home-roles-0.22.0`.

## Review Focus

1. **A role home whose cards the person can't use** (Requester given only My work and Low stock): the person gets today's dashboard if they have dashboard.view, otherwise the "nothing to show yet" message, never an empty page. Test: Vitest `homeChoice falls back when no card is usable` (Task 6).
2. **A pinned view for a list the person can no longer open**: the tile shows "No access" and makes no request. Test: Vitest `counterAccess says no access without the list permission` (Task 8).
3. **A saved view query with unknown or stale keys** (an old key, a deleted site id): the query function drops unknown keys and the count is whatever the list says (0), no error. Test: Vitest `apiQuery ignores keys the list doesn't know` (Task 5).
4. **Role names differing only in case, or renamed**: merge order is case-insensitive by name and follows renames. Test: `Home_merges_in_case_insensitive_name_order` (Task 2).
5. **Deleting a role that has default columns and is part of someone's merge**: the delete succeeds, its defaults go, and that person's list settings and `/auth/me` still answer. Test: `Deleting_a_role_removes_its_default_columns` (Task 3).
