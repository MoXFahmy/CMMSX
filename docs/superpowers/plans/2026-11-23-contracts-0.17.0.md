# Contracts and contractors (0.17.0) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Suppliers become companies (supplier / contractor / manufacturer roles, extra contacts and addresses, contractor categories and rates); contractor lines on work orders costed into every cost report; service contracts with periods, amendments, covered assets, automatic renewal, alerts (bell and e-mail), links from work orders and PMs, and a contract report.

**Architecture:** Companies stay in the `Suppliers` table with new role columns and child lists. A `WorkOrderContractor` table sits beside labour, parts and other costs; `ReportEndpoints.CostLinesAsync` gains a Contractor amount (contractor lines plus labour of company-linked employees, moved out of Labour). Contracts get their own tables in a new Core namespace `FourC.Cmms.Core.Contracts`. A pure `ContractTerms` class does the date rules (periods, status, deadlines, renewals, expected counts). A `ContractNotifier` background service, built like `OverdueNotifier`, renews contracts and sends the alerts.

**Tech Stack:** ASP.NET Core 10 minimal APIs, EF Core 10 (SQL Server, named Tenant/Site filters), React 19 + Mantine 8 + mantine-datatable + TanStack Query + i18next, xUnit integration tests against SQL Server, Vitest.

**Spec:** `docs/superpowers/specs/2026-11-23-contracts-0.17.0-design.md`

## Global Constraints

- No new NuGet or npm packages.
- Arabic for every new screen text (web `en.json` + `ar.json` via `loc-add.py`, Arabic plurals `_zero/_one/_two/_few/_many/_other`); every new server message through `Translator.T` with an entry in `server/FourC.Cmms.Api/Localization/ar.json` (`ar-add.py`).
- Organizations that use none of this see no change: no contracts and no contractor lines → screens and reports as before, a Contractor column showing zeros is fine. Every existing test stays green unchanged, except tests that assert the exact column list of a cost report (update those for the new `contractor` column).
- Permissions exactly: `contracts.view` "View contracts" (Administrator, Maintenance Manager, Technician, Viewer) and `contracts.manage` "Create and edit contracts" (Administrator, Maintenance Manager). Companies, contractor categories and company rates: `suppliers.manage`. Contract types: `contracts.manage`. Contractor lines: `workorders.edit` adds, edits and removes them; `workorders.execute` records hours done, date done and person on existing lines.
- Numbers `CON-00001`: one organization-wide sequence `"Contract"`, no site prefix, 5 digits.
- Contract status is computed, never stored: `Upcoming`, `Active`, `Expired`, `Terminated`.
- Period rule: a period of N months runs from its start to start + N months − 1 day. When adding the months clamps to a shorter month, the period ends on that month's last day (starting 31 January for one month ends 28/29 February). A renewal starts the day after the previous end.
- Notice deadline = end − notice days (automatic renewal only); end alert = end date (no automatic renewal). Alert window = alert days before the deadline, up to and including it. A termination date stops renewal and alerts at once.
- E-mail switch key exactly `contract.alert`: fixed recipients, on by default, personal opt-outs apply. Recipients are the manager plus Settings › Contracts alert recipients; when both are empty, everyone with `contracts.manage`. Each recipient must be able to see the contract's site.
- Rates are copied onto the line when it is added and when its category or company changes. A later change to a category or company rate never changes a recorded line.
- A company that loses its Contractor role or goes inactive keeps its existing lines, contracts and employee links. Pickers stop offering it, and the server refuses it only when it is newly chosen.
- Refused actions say why (400 with a message), never silently do nothing.
- Commands (scratchpad `bin` on PATH, `export WT=/Users/mohamedfahmy/Projects/CMMSX/.worktrees/contracts-0.17.0`): server tests `wt-test [filter]`, web tests `wt-vitest`, web build `wt-web`, migration `wt-ef <Name>`.

## Review Focus

1. **Double counting.** A work order with a contractor line, a company-linked employee's labour and an unlinked contractor employee's labour: the first two are counted once, in Contractor; the third stays in Labour. This holds on the work order totals and in every cost report. Tests: `Work_order_totals_move_company_linked_labour_to_contractor` (Task 3) and `Contractor_line_and_company_linked_labour_count_once_in_contractor` (Task 4).
2. **Renewal and alerts.** Renewal must catch up several missed periods (service down for months), handle starts on the 29th–31st, and never send an alert twice after a renewal or a restart. Tests: `Period_end_clamps_to_month_end` (Task 5, pure), `Auto_renewal_catches_up_missed_periods_and_month_ends` and `Alert_email_goes_once_per_deadline_and_again_after_renewal` (Task 6).
3. **Site access.** A site-limited user sees organization-wide contracts and their own site's, never another site's. Covered assets at other sites don't leak, and saving the contract keeps them. Bell counts and alert e-mails follow site access. Tests: `Site_limited_user_sees_organization_wide_and_own_site_contracts_only` (Task 5) and `Bell_and_alert_emails_respect_contract_sites` (Task 6).
4. **Company losing its Contractor role or going inactive.** Existing lines, contracts and employee links keep working and save unchanged; pickers stop offering the company, and newly choosing it is refused. Tests: `Company_losing_contractor_role_keeps_existing_lines` (Task 3) and `Company_losing_contractor_role_keeps_existing_contracts` (Task 5).
5. **Rates.** Changing a category's default rate or a company's rate never changes a line already added. Test: `Rate_change_never_changes_recorded_lines` (Task 3).
