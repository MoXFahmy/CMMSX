## Design points that look hard or impossible as written (one line each)
- 0.9.1-1: the design says the count should match "the list its link opens (organization's local dates)", but the list filter is UTC midnight (`WorkOrderEndpoints.cs:772-774`) and the link date comes from the browser clock, so both ends must change, not only the count.
- 0.8.0-6: `Asset.RunsHoursPerDay` is a non-nullable decimal and the DTO cannot tell "left out" from "cleared" (an existing test pins "left out keeps"); "clears the value" needs a manages-flag and a decision on what a cleared value stores (24, or a migration to nullable).
- 0.13.0-2: the removed step's name no longer exists on the server (rows deleted), so "a note naming the step" needs the phone to send the step text with the photo, or an audit-log lookup.
- 0.16.0-5: a unique index on `PurchaseOrderLines.PurchaseRequestLineId` would also block re-ordering after an order is cancelled (cancelled orders keep their links); "live" needs a flag column, clearing the link, or a lock instead of an index; existing duplicates must be handled in the migration.
- 0.11.0-11 (requesters without an employee link): the phone shell only registers push inside the tech app, and people without an employee link are redirected out of it; registering them needs push code in the full web app too.
- 0.15.0-3: needs a new column on `AiDiagnoses` (migration) and the "whole organization" test must use the person's full access, not the site-switched scope that `ITenantContext` carries.
- 0.17.0-1: the refusal "with the list of those lines" would leak work-order numbers of sites a site-limited editor cannot see; list visible lines only plus a count.
- 0.26.1-3: today's message names the asset number; for hidden assets it would leak the number - use a number-free message.
- Security check, "missing gitleaks report after a clean run is a problem": may be impossible if the pinned gitleaks writes no report when it finds nothing (existing comment says so); verify against the image first.
- 0.18.0-13 and 0.20.0-9 are described as "server error"; by code they already surface as a 409 with the generic duplicate text (unique indexes exist), so the work is the message, not the status.
- 0.20.0-3: "current month by days elapsed" vs a report that takes any From/To; the rule has to say whether it prorates the month containing `a.To` or only the month containing today.
