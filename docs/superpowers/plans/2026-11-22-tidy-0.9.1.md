# 0.9.1 tidy-up Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Fix the nine small items the 0.9.0 final review deferred, plus the PM round that loses its hidden assets.

**Architecture:**
- These are small changes to the 0.9.0 code.
- Server rules sit next to the ones they extend: `AdminEndpoints.OutsideAsync`, `SiteAccess.VisibleAsync`, `TeamEndpoints`, `PlanningBoardEndpoints`, `LocationEndpoints` site settings, the asset importer and `PmEndpoints`.
- Web changes are in the user form, the work order and PM forms, the dashboard and the work order list.

**Tech Stack:** ASP.NET Core 10, EF Core 10, xUnit; React 19, Mantine 8, Vitest.

**Spec:** 0.9.0's `docs/superpowers/specs/2026-11-22-sites-access-0.9.0-design.md`, and the deferred minors of its final review (copied below).

**Commands:** `B=<scratchpad>/bin`; `$B/wt-test`, `$B/wt-vitest`, `$B/wt-web` (pointing at `.worktrees/tidy-0.9.1`).

## Global Constraints

- **No migration.** Every new text goes in `en.json`/`ar.json` or the server `ar.json`.
- **Older clients keep working.** In particular, a work order or PM schedule saved without the new `managesTeam` flag keeps its team.
- **Commits** end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Items and tests

Each item is fixed test-first: write its test, watch it fail, fix, then pass. All server tests go in `server/FourC.Cmms.Tests/TidyAccessTests.cs` unless noted.

1. **A user whose places were all deleted can be edited.** `CheckAccessAsync` reports "Unknown location." only for ids that are new to this save. Deleted ids stay stored, so the person still sees nothing. The user form shows a stored id it can't find as "(deleted place)" so it can be removed.
   - Test: `A_user_whose_places_were_deleted_can_still_be_edited`. Rename → 200; their access stays nothing.
2. **Device sign-out follows the same rule as other user changes.** Listing or signing out another person's devices uses `OutsideAsync` (moved into a shared `UserAccessRules`).
   - Test: `A_limited_admin_cannot_sign_out_people_who_see_more` → 400.
3. **The audit trail of site-owned child records answers "not found" outside the person's sites.**
   - `SiteAccess.VisibleAsync` checks the child types through their filtered sets: WorkOrderLabor, WorkOrderPart, WorkOrderCost, WorkOrderTask, WorkOrderComment, StockLevel, StockTransaction, AssetPart, AssetTransfer, PurchaseOrderLine.
   - Shared types are allowed: Part, PartGroup, Supplier, PmTask, Employee, Trade, FailureCode, AssetCategory, CustomFieldDefinition.
   - Any other type is refused for limited requests.
   - Test: `Audit_of_another_sites_labour_is_not_found`.
4. **An older page doesn't clear a team.**
   - `WorkOrderInput` and `ScheduleInput` gain `bool? ManagesTeam`. An edit without it keeps the current team; new web forms send `managesTeam: true`. Creating always applies `TeamId`.
   - Test: `An_edit_from_an_older_page_keeps_the_team` (PUT without the flag keeps the team; with `managesTeam: true` and no team, it clears).
5. **Teams and sites.**
   - A team's site can't change to a site other than that of its open work and schedules ("This team has open work or PM schedules at another site.").
   - People with limited access must give their teams a site (unless the team already has none and its site doesn't change).
   - Test: `A_teams_site_follows_its_work_and_limited_people_give_a_site`.
6. **The planning board lists only people who work at a visible site** (or at every site) for limited requests.
   - Test: `The_board_shows_limited_people_only_their_sites_technicians`.
7. **A site's request recipients must be able to see the site** ("Choose people who can see this site.").
   - Test: `Request_recipients_must_see_the_site`.
8. **Import auto-numbering skips numbers used in hidden sites.** For limited requests, the importer also loads every asset number (`AllSites`) into a set it checks.
   - Test: `Import_numbering_skips_numbers_used_in_hidden_sites` (a hidden asset holding the next number → the new row gets the following one, with no error).
9. **Dashboard and filter badge.**
   - The "Completed (30 days)" links open work completed since 30 days ago. A new `completedFrom` filter on the work order list has a chip, and it is counted by "More filters".
   - The More filters badge counts `teamId`.
   - Tests: `Completed_from_filters_the_list` (server); web build.
10. **A PM round keeps the assets the editor can't see.** Saving a round with `AssetIds` keeps the round's assets that are hidden from the person, after the ones they sent.
    - Test: `Saving_a_round_keeps_assets_the_person_cannot_see`.

Then: `CHANGELOG.md` 0.9.1 section; `$B/wt-test`, `$B/wt-vitest`, `$B/wt-web`; one fresh reviewer on the branch.
