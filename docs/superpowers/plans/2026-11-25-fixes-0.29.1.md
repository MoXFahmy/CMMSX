# CMX 0.29.1 Privacy and Data-Safety Fixes Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fix the 42 urgent left-overs from 0.6.0–0.28.0 (leaks, a skippable safety gate, silent data loss, wrong totals, races,
server errors), add a guard test against filter-lifting leaks, and close four operations gaps left by 0.29.0.

**Architecture:** Fixes go into the existing endpoints, services and screens, in each area's own files. No new modules. One
migration (the AI diagnosis history column, Task 2). Concurrency fixes use row versions, transactions and the existing 409
mapping. Infrastructure changes go through `infra/aws/*.yml` and `deploy-aws.yml` only.

**Tech Stack:** ASP.NET Core 10 minimal APIs, EF Core 10 / SQL Server, xUnit `[SkippableFact]` with `ApiFixture`, React 19 +
Mantine + Vitest, Capacitor phone shell, CloudFormation, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-11-25-fixes-0.29.1-design.md` (read it first).
**Code map:** `docs/superpowers/plans/2026-11-25-fixes-0.29.1-code-map.md`, from a read-only survey at 3ebac17. Each item has a
block with where the problem is, whether it's still present, the tests to extend and the migration question. Section 0 lists the
shared helpers. Read your items' blocks before writing tests.

## Global Constraints

- Tests first for every item: write the test, run it, see it fail on the current code, then fix. If it passes before any fix, the
  item is already closed. Keep the test, record "already fixed" in the report, and change no code for it.
- Server tests: `[SkippableFact]` + `Skip.IfNot(fx.Enabled, ...)` with the `Loop`/`OrgAsync`/`UserAsync` helpers (code map §0).
  Concurrency tests run the competing calls with `Task.WhenAll` and assert the final database state.
- Every new user-facing text has English and Arabic: server `server/FourC.Cmms.Api/Localization/ar.json` (key = exact English
  text) through `Translator.T`; web `web/src/locales/en.json` + `ar.json`. Each task adds its new server messages to a
  `New_messages_have_Arabic`-style `[Theory]`.
- No IP address or e-mail address in any log line.
- "Can see" checks for stored or shared content (diagnoses, recipients, approvers) use the person's whole access
  (`Access.Of(http)` / `AccessService.GetAsync(userId)`), never the `X-Cmx-Site`-switched request scope.
- Messages never name records the reader can't see (no work-order or asset numbers from hidden sites).
- Exactly one migration in this release (Task 2). Any other task that thinks it needs one stops and reports.
- Clear errors use the existing patterns: `DomainException` → 400, `DbUpdateConcurrencyException` → 409 "This record was changed by
  someone else. Reload it and try again.", `Validator(...).Problem()`, `Results.Problem(title: Translator.T(...), statusCode: 409)`.
- Older phone builds must keep working: a new optional field the phone may send is optional on the server, and leaving it out
  keeps today's behaviour.
- Commit messages end with the line `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Stage only your task's files. Never
  push. Never run anything against AWS or GitHub.
- Test helpers (Docker, against the local SQL container; run one at a time) live in

## Rulings made while planning (from the code survey)

- **P1 (0.9.1-1):** fix both ends. The counter and the list its link opens both use the organization's local dates, and the
  link's date comes from the organization's time zone, not the browser.
- **P2 (0.8.0-6):** "cleared" means back to the default of 24 (all day); the column stays non-nullable.
  - The input gains `bool ManagesRunsHoursPerDay`, following the project pattern (`ManagesCostCentre`).
  - The web form sends `true`, so an empty box means 24.
  - Inputs that leave it out keep the old value. `DowntimeTests.Running_time_must_make_sense` stays green.
- **P3 (0.13.0-2):** the phone sends the step's text with the photo, as a new optional field. The server's note uses it.
  Older phones get the note "Photo for a step that was removed".
- **P4 (0.16.0-5):** no new unique index, because cancelled orders keep their links and a unique index would block re-ordering.
  - Linking an order line to a request line writes to that request line under its row version.
  - Two buyers at once: the second gets 409, "This request line was just ordered by someone else."
  - Existing data is untouched.
- **P5 (0.11.0-11):** registering push for phone users without an employee link needs push code in the full web app. That part
  moves to 0.39.0 (iOS and phone). 0.29.1 fixes the "Request approved" link and the guide's wording.
- **P6 (0.15.0-3):** the migration adds a column holding the ids of the history work orders given to the model. The check uses
  the person's whole access. The existing test `Listed_sources_hide_what_the_viewer_cannot_see` is rewritten to the new rule.
- **P7 (0.17.0-1):** the refusal lists only the lines the editor can see, then "and N more you can't see".
- **P8 (0.26.1-3):** the refusal message names no asset.
- **P9 (0.20.0-3):** any month the report range only partly covers counts by the days it covers. A range ending today therefore
  counts the current month by days elapsed; full months and full years are unchanged.
- **P10 (0.12.0-13):** `Recipients_without_access_get_nothing` becomes a refusal test. Mail still drops anyone without access,
  as a second line of defence.
- **P11 (guard test):** the scan works one C# statement at a time (split on `;` outside strings and comments). It flags any
  statement where `AllSites()` or `IgnoreQueryFilters(` appears together with a site-visibility helper: `SiteAccess.VisibleAsync`,
  `Access.Covers`, `CurrentSiteIds`, `CurrentBranchPaths`, `.Visible(`.
  - An allow-list file holds `file:approx-line` and a one-line reason per entry.
  - A unit test feeds the scanner the 0.26.1-3 statement from before the fix and expects a hit.
- **P12 (security check):** the implementer runs `zricethezav/gitleaks:v8.21.2` on a clean tree once.
  - If it writes no report on a clean run, a missing report after exit 0 stays "clean", and a code comment says so.
  - If it writes `[]`, a missing report counts as a problem.

## Review Focus

1. **Branch-limited people:** limited to part of the location tree, not just a site. Every visibility fix (Tasks 1–2) is tested
   with such a person as well as a site-limited one.
2. **Older phones:** payloads without the new optional fields (Tasks 3 and 7) behave as before. Each task has a test that sends
   the old payload.
3. **Arabic:** every new server message appears in a `New_messages_have_Arabic`-style theory, and web text in both locale files
   (`locales.test.ts` enforces parity).
4. **Real concurrency:** race tests (Tasks 3, 5 and 6) fire the competing calls together and assert the database afterwards, not
   only the HTTP codes.
5. **Live data:** Task 2's migration runs on a database with existing diagnoses. Old rows stay readable for people whose access
   covers the whole organization, and are hidden from everyone else.
